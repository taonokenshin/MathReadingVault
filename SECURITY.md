# Security and privacy

Run demonstrations only with their disposable roots. Public defaults use repository-local configuration; a deliberate real integration must supply its own private paths and scheduler adapter. The controller coordinates trusted local tasks and is not a security boundary against hostile processes.

Never upload credentials, API keys, account IDs, private automation memory, live lock owners, source PDFs, caches or learner data. Keep library.yml, runtime and .local-automations/ private. Public tests need no API key. A suspected credential exposure should be removed and the credential revoked by its owner; do not paste it into an issue.

Report non-sensitive reproducible software problems in a GitHub issue. For a sensitive issue, use GitHub's private vulnerability reporting if available; otherwise ask the maintainer for a private channel without including the secret or exploit data in a public post.
